## Covered expectations

- Valid structured proposal and explicit configured model; provider independence.
- Strict journey validation, unknown fields/operations/parameters, invalid dependencies/bindings,
  hallucinated destinations, controls, exclusions and forged phase fields.
- Malformed/refused/non-JSON/schema-invalid or over-64-KiB output: MODEL PLAN ERROR, one attempt.
- Provider outage/429/timeout: MODEL ERROR, no retry, no provider exception payload disclosure.
- Pre-call and in-flight cancellation; a provider ignoring abort cannot extend the shared deadline.
- Model deadline capped by configured timeout, remaining run time and 30 seconds.
- 128-KiB sanitized context cap; known configured/issued and designated response secrets are symbolic.
- Captured model context excludes evaluator-private metadata and contains only exploration candidates.
- Token metadata retained; missing successful usage estimates UTF-8 bytes/4, rounded upward.
- Invalid output rejects immediately; the existing BudgetManager stops on three valid non-useful
  rounds and clears stagnation on useful planning. T033 must wire novelty and these calls to the
  supervised exploration loop; this checkpoint does not claim that integration is implemented.

Failed-call durable telemetry, exact SDK request configuration (no tools, retries attempts:1),
provider failure output usage explicitly unknown, and run-record model persistence remain T032/T033
implementation obligations under FR-026/028/029. Tests currently cannot prove those integrations.

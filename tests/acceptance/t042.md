## Exact identity and intended assertion

The generated export boundary rejects extra fields, external verification claims,
VERIFIED inputs, changed canonical bytes/hash and conflicting envelope data before
writes/admission. Durable source loading checks originating run/project/finding,
consistent confirmation, exact predicate ID/version/hash/provenance, approved eligibility
as of run acceptance, reset ID/version/definition, best verified journey/dependencies,
API operation/method/path/schema expectations, passive scope template and symbolic slots.
Every referenced original/replay/minimization trial is loaded through existing durable
checks. Expected deterministic content must equal the exact supplied manifest/envelope.
No Gemini regeneration, interpretation or classification occurs.

Execution uses the supplied manifest's exact declarative journey. A fresh execution
record receives its own UUID while retaining all operation/step definitions and bindings;
the source journey/manifest ID and bytes remain immutable and are recorded in provenance.
Reset comes from the existing frozen supervisor configuration, already checked equal to
manifest reset. Runtime values are generated/re-extracted for that new trial.

Predicate conjunction and each assertion are evaluated by the existing deterministic
engine. Assertion references are predicate ID:version:hash:assertion:index. Intended
failing references are common to discovery, independent confirmation and best verified
reproduction evidence. VERIFIED requires the exact eligible predicate to evaluate
VIOLATED and an intended assertion to fail again. A different failed assertion of the
same predicate cannot substitute. SATISFIED, NOT APPLICABLE, UNEVALUABLE, missing intended
failure, execution errors and external results do not verify. No approved definition is
mutated; per-assertion evaluator views are transient only.

## Authority, freshness and budget

The existing path remains:

```text
exact manifest → establishFreshState / executeJourney → existing engine intents
→ RunSupervisor → BudgetManager → frozen phase/scope/operation policy
→ cancellation/ownership checks → sole deterministic executor
→ deterministic predicate/assertion evaluation → guarded evidence/status commit
```

Full-trial admission precedes reset. Every executed artifact has its own reset, verified
baseline, trial ID, execution records and evidence. Returned baseline data must match the
supervisor's active trial and actual durable baseline, and cannot reuse any earlier trial
or baseline. Invalid/stale/reused/missing/failed/unevaluable baselines close the gate before
artifact actions. Credentials are injected only by the existing protected supervisor
runtime; the manifest/report/audit contains symbolic slots and sanitized references.

All-phase used budget is 34 before artifact verification. Limit 39 admits reset + baseline

- three actions and ends at 39; limit 38 rejects before reset. There is no new counter,
  BudgetManager, deadline or independent budget. Cancellation/lock loss prevent new dispatch.
  A failure after persisted intent conservatively charges that intent without a target
  response/refund or VERIFIED status. Reset, baseline, execution/storage failure, time stop
  and shutdown remain honest run/trial outcomes. Finding confirmation and its historical
  transitions are never rewritten by artifact verification.

## Commit and append-only persistence

Registration persists exact manifest bytes/hash/version as UNVERIFIED. Verification
extends the existing immutable evidence table with ARTIFACT predicate evidence and an
ARTIFACT VERIFICATION audit carrying source/execution identity, baseline, actual admitted trial identity when available, verdict,
assertion references/evaluations, intended references, reason, verification time and
supervised provenance. Failure audits remain explicitly unverified; unavailable storage
is reported as UNAVAILABLE rather than pretending evidence was persisted. Reset failures
before the first intent retain FreshStateError's actual admitted trial ID, including when
no request was dispatched. Unadmitted failures have an audit grouping UUID only; no
trial/baseline/verdict is fabricated.

Status mutation uses existing BEGIN/COMMIT/ROLLBACK and row locks on finding/artifact/run.
Before granting VERIFIED, the repository checks live supervisor/trial authority, actual
session ownership of the existing PostgreSQL advisory lock, active durable run/deadline
and absence of cancellation. The conditional status SQL checks those durable conditions
again. After all awaited evidence/status writes, authority is rechecked before COMMIT
submission, with no intervening await. This submission is the authorization commit point;
subsequent cancellation cannot erase a historical commit already authorized/completed.
No additional lock is acquired and reacquisition cannot reopen a closed supervisor gate.

Cancellation, gate ownership loss and actual advisory-lock release during the pending
status write all roll back VERIFIED and the pending verification audit. A separate honest
failure audit may then be appended if storage is available. Completed predicate observations
remain actual observations, never converted to execution-error predicate verdicts. Artifact
content/hash, historical evidence references and VERIFIED history cannot be changed/deleted.
An already verified identity cannot be submitted as a new generated verification attempt
or silently borrow its old status for edited bytes or independent results.

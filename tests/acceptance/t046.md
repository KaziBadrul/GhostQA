to `runVerticalSlice` reproduction mode. `fixtures/required.ts` is an evaluator
configuration adapter: it validates the existing private registry, constructs

## Selection, authority and blinding

Required selection is exactly order-lifecycle, inventory, workflow, each faulty
and repaired with five independent assignments: **30 assigned trials**. No
supplemental fixture is loaded. Supplemental selection fails closed while the
optional suite is unavailable; T058 is not implemented.

Each execution starts an owned loopback fixture and isolated database schema,
creates explicit frozen scope/phase approval and uses the existing originating
RunSupervisor and its BudgetManager for every target request. Default limits are
200 requests, 600000 milliseconds, 20 exploration journeys, 10 steps, 10000 ms
request timeout and 30000 ms model timeout. Each assigned run and every executed
trial receives fresh identities, reset and a newly verified baseline. Schema
cleanup occurs after evidence has been read/written; it never cleans up the
application's originating historical schema. Fixture clients are not added to
the harness; the existing authoritative dispatcher performs target execution.

Variant labels, expected action sequences and fixture-private result metadata
remain evaluator fields in the assignment ledger. Configuration passes only the
neutral public API, approved invariant, frozen phase policy, reset/baseline
contract and explicit model identity to the engine. Planner context excludes
control candidates. The autonomous CLI uses only the real configured Gemini
provider; the supplied evaluator journey is unreachable in that mode.

## Frozen identity and durable results

Before a series, record SHA-256 identities for:

- Engine/server/transport/CLI sources, package metadata and worker build script.
- Prompt adapter, structured-output schema and planning-context source.
- Dependency lockfile, explicit provider/model identity and Node runtime.
- Required-suite registry, fixture source/public contracts and configuration adapter.
- Compiled engine/import workers and configuration/default limits.

The full sorted source-hash maps accompany the aggregate hashes. Actual immutable
run configuration has its own per-trial hash, including frozen target approval.
`series.json` contains all assigned identities before execution. Each assignment
and final result is written separately with exclusive creation; reruns cannot
overwrite an existing series. Exported manifests, reports, packages and sanitized
execution/evidence records are retained in per-assignment directories when
available. Frozen identities are rechecked before every assignment and after the
last; drift stops further execution and invalidates the series without replacing
completed records. No retry is introduced.

Cancellation/interruption/error assignments remain in denominators. Missing or
malformed result files can be inspected with `readBenchmark`; they become honest
interrupted/invalid results, with no automatic execution/resume. Discovery and
confirmation rates are computed separately out of all five assigned trials for
each required pair; repaired confirmations use that same denominator for the
false-positive rate. These computed harness rates are not a discovery claim.

A non-executing configured-model identity snapshot is retained in
`t046-freeze.json`. It is not a T048 measurement or proof of model availability;
a later live series must freeze its own then-current build/configuration.

## FR-029 metrics

Records retain assignment/run/trial identity, baseline verdicts, discovery and
confirmation outcomes, terminal stop reason, authoritative phase/total requests,
exploration journeys, model calls including failed calls, exact configuration
hash and original/best journey lengths excluding control steps.

Usage comes from persisted planning intent/result evidence. Available provider
counts take precedence. Otherwise available sanitized UTF-8 input/output bytes
are estimated with ceiling(bytes / 4), labeled ESTIMATED. Unavailable output on
failed calls, missing counters and absent reproducer lengths remain explicitly
UNKNOWN/null, never invented zero. Aggregation stays UNKNOWN when any constituent
usage is unavailable. Gemini counts remain provider counts even when its combined
usage flag also describes a missing counterpart. No raw provider exception is
persisted by the harness.

## Production contract

`ReasoningProvider.propose(SanitizedPlanningContext, AbortSignal)` returns
`{ proposal, provider, model, usage }`. Engine code uses this provider-independent
interface; SDK types and behavior are confined to the Gemini adapter.

Context has exactly `api`, `mappings`, `observations`, `approvedPredicateRefs`,
`symbolicInputs`, `remainingLimits` and `consideredHypothesisHashes`. The API includes
only eligible exploration operations; control-linked mappings/observations are omitted,
and import diagnostics are withheld. Model configuration, credential bindings/values,
reset/check definitions, resolved addresses, approvals and evaluator-private metadata
are not copied into this context. The context builder uses the trial vault and schema-aware
sanitization, including a second pass for secrets discovered in schema examples. Operation
identifiers, schemas and sanitized descriptions remain planning data, not network authority.

Context is at most 128 KiB. Gemini receives it as JSON user data with a fixed system
instruction identifying all target text as untrusted. No tools/function calling are enabled.
The response is a JSON Journey; Zod-derived SDK schema guidance uses the SDK-supported
subset with bounded JSON-template expansion. Unsupported SDK guidance keywords are omitted,
while full runtime constraints remain unchanged and authoritative. This guidance does not
modify imported OpenAPI schemas or executor validation.

The boundary accepts at most 64 KiB of structured output and applies strict Zod, dependency,
operation, phase, parameter/body and binding checks using private API/scope snapshots.
It compares predicate ID, version and hash against the admitted context references exactly;
no substitution, normalization or repair is performed. Configured step limits and secret
literal checks apply. Unknown authority fields and reset/baseline/excluded actions fail.
Only a validated proposal is returned; no requests, baseline evaluation or findings occur.

## Adapter, errors and telemetry

The model must be explicit; no fallback or free-tier availability assumption exists.
Gemini identity is returned with each proposal and safe failure telemetry. Existing run
configuration persistence remains intact; T033 will integrate proposal telemetry and
supervisor-owned model-call accounting into orchestration and durable run records.

The adapter streams one candidate, caps accumulated UTF-8 output before JSON parsing,
and configures JSON schema output, maxOutputTokens, AbortSignal, HTTP timeout and
retryOptions attempts:1. SDK request shape and a real SDK mocked-fetch 429 path are tested.
The outer boundary caps the call by configured timeout, 30 seconds and remaining run time,
including context-processing elapsed time; it rejects late results even if a provider ignores
abort. Cancellation aborts and rejects; it does not claim provider computation/cost rollback.

Malformed/refused/oversized/unauthorized output is MODEL PLAN ERROR. Provider outage,
429 and timeout are MODEL ERROR. Exceptions expose constant reasons and safe telemetry,
never raw provider errors/output or keys. There are no retries or repair calls.

Reported token usage is retained. Missing successful usage uses ceiling(sanitized UTF-8
bytes/4) separately for input/output and sets estimated:true. Failed calls retain an input
estimate and leave unavailable output usage absent/unknown, never zero. Invalid structured
replies retain available reported usage. The boundary returns attempt metadata rather than
maintaining a model-call authorization counter. Existing BudgetManager tests verify three
valid non-useful rounds stop and a useful round clears stagnation; T033 owns novelty/loop wiring.

SDK compatibility references:
[HttpOptions](https://googleapis.github.io/js-genai/release_docs/interfaces/types.HttpOptions.html),
[GenerateContentConfig](https://googleapis.github.io/js-genai/release_docs/interfaces/types.GenerateContentConfig.html).
Locked installed declarations were checked for stream, schema, timeout, abort and retry behavior.

## Limitations and next work

This is a mocked-provider boundary proof, not autonomous discovery or benchmark acceptance.
SDK schema acceptance, availability/quota and discovery rate for the developer's explicitly
configured live model remain live-gate checks. Arbitrary unmarked unknown secrets cannot be
perfectly detected, and JavaScript cannot promise secure erasure. These accepted limitations
remain unchanged. No globally guaranteed immunity to model prompt injection is claimed;
deterministic authority checks prevent output from granting execution permissions.

T033 is the exact next task. It has not begun.

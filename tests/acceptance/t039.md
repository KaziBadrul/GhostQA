## Algorithm and authority

Input must match the durable, consistent CONFIRMED finding, immutable original
journey and run snapshot. Initial and independent confirmation evidence are loaded
and validated, with eligible predicate approval as of immutable run acceptance.
Active supervisor run identity is checked before admission/reset. Caller edits
cannot expand scope, rewrite predicates or substitute original journey evidence.

Scan single-step removal indexes in stable retained order. Protect predicate
operands on either side, including extracted variables; protect required producers
and prerequisites. Retained definitions, predicate ID/version/hash, dependency
semantics and action order remain unchanged. Invalid local candidates are rejected
without target budget consumption. On acceptance, restart the ordered scan with
the shorter best. A normalized candidate hash set avoids equivalent replays;
bounded scans and strictly decreasing accepted action count ensure termination.
No Gemini call selects removals, evaluates predicates or accepts reductions.

Each executable candidate uses the existing establishFreshState/executeJourney
path: complete admission, reset, checks, verified independent baseline, ordered
execution and deterministic evaluation. RunSupervisor owns the same BudgetManager,
frozen scope/phase policy, cancellation and sole HTTP dispatcher. No minimizer
transport, shadow budget or alternate reset/replay implementation exists.

Accept only exact eligible VIOLATED, with new trial/baseline/observations and
matching authoritative deterministic evaluation. SATISFIED, NOT APPLICABLE,
UNEVALUABLE, missing/ineligible evidence and different predicate identity do not
accept a reduction. Production evaluates transient trial-local values before
vault disposal; symbolic persisted observations cannot substitute for unavailable
secrets/configured inputs. The pure test boundary checks deterministic observations
and cannot accept a forged verdict/model explanation over satisfied evidence.

## Budgets, failures and stopping

Admission counts all reset/check/candidate requests through the original manager.
Limits 22 deny the first candidate before reset; 23 and 28 admit only the first
reduction and retain the five-step verified best. Execution/cancellation/deadline,
reset, baseline, invalid freshness, lock loss, shutdown or storage failure closes
the existing gate and retains the last verified sequence. Failed attempts never
manufacture predicate verdicts or change historical confirmation classification.
Cancellation during intent persistence prevents a response and retains conservative
budget accounting. Admitted reset failures retain actual trial identity, even
before a target intent. Partial failures retain available sanitized observations.

A full scan with no preserving permitted deletion reports LOCAL MINIMUM and
locallyIrreducible=true. Interrupted work reports its real stop code and false
local-criterion status. This is the shortest verified sequence found by this
ordered single-step strategy; no globally shortest claim. Later invocation keeps
a durable previously minimized best, including when the supervisor is stopped;
it does not resume stopped target execution or restore the original longer best.

## Append-only persistence

MINIMIZATION ATTEMPT evidence records source finding/original journey, exact
predicate, candidate, removed step, decision/reason, available fresh trial,
baseline, observations/evaluation and resulting best. MINIMIZATION RESULT records
best/stop/local-criterion metadata. Existing immutable evidence guards prohibit
updates/deletion. Local rejections have no execution trial in their attempt payload;
the evidence table's required UUID is only an audit-event grouping identity, like
existing non-execution planning evidence, and does not claim a reset/replay occurred.

Executed references are checked against durable trial evidence. Accepted deletion
is revalidated against the row-locked current best using shared deletion rules.
The accepted candidate and new best must match exactly. Stale/larger updates are
rejected without changing history. Derived minimized journey/stop fields update
atomically; original journey, initial/replay evidence and finding transitions remain
immutable. No finding classification or eligibility comes from the model.

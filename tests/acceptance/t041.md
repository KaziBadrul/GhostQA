## Manifest identity and content

Manifest format version 1 contains exact reset specification and baseline assertions,
best verified journey with dependency/extraction declarations, exact eligible approved
predicate plus deterministic assertions, predicate ID/version/canonical hash, API
operation/method/path/schema expectations, passive scope template, symbolic credential
slots/header bindings and run/finding/original/best/evidence references.

Scope template excludes pinned addresses and approval ID, and grants no invocation
permission. No credential values/versions, originating budget, model configuration,
worker, signal or database capability are exported. Later invocation requires new
explicit destination/address/operation approval, finite limits, mutation acknowledgment
and separately supplied credentials. No independent runner is implemented here.

Canonical serialization reuses detection/predicate.ts's sorted-object representation;
arrays preserve meaningful order. SHA-256 covers exact versioned manifest bytes.
Artifact ID and timestamp are envelope metadata and do not change executable identity.
Predicate hash, mirrored assertion data, binding slots and dependency structure are
validated. Relevant edits change identity or fail validation. At T041 contentHash
identifies the manifest itself; no runner/package hash or verification is claimed.
T043 will separately identify a bundled package. Old verification cannot apply to edits.

Source must be a consistent eligible CONFIRMED finding with independent initial/replay
baseline references and exact original/best predicate identity. Accepted reductions are
checked in sequence by the existing preservation validator against each previous best,
with independent trial/baseline IDs, exact deterministic violation and retained operation
semantics. The final best must match that verified chain; missing/edited/unverified best
cannot generate an executable artifact. Existing runtime validation remains intact.

## Reports and secret safety

Reports include finding history/status/consistency, source and approval reference as of
run acceptance, exact predicate identity/definition, original and best journey lengths,
discovery/confirmation/baseline observations, minimization attempts and reasons, execution
provenance, truncation and local stop reason. Markdown gives readable assertions, ordered
operations and evidence references plus formatted sanitized JSON. JSON retains the complete
structured chain. The claim is shortest verified sequence found; local irreducibility is
reported only after a completed algorithm scan, never as a global minimum.

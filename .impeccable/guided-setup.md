# Guided project setup

Operate mode; preserve the existing charcoal, blue-accent developer interface. Developers should reach their first supervised API test without navigating an undifferentiated configuration form.

Six steps: specification; target/operations; optional authentication; fresh-state checks; expected behavior/explicit approval; review and execution approval. Saved project state chooses the first missing required step. Users can revisit steps or show all settings. Unsaved definitions cannot silently become execution configuration; credentials are never placed in browser progress storage.

Use a compact numbered step navigation with textual Saved/Required/Optional/Approved states, one active group, concise contextual help, Back/Continue controls, and a saved-state review. Keep existing advanced JSON editors and approvals. Step navigation uses real buttons and moves focus to a named heading; hidden groups are removed from keyboard navigation. Navigation stacks from six columns to three below 900px and two below 600px. No decorative animation.

Actionable errors provide a title, a concrete cause, fixed recovery guidance, safe field details and links to relevant setup steps. Run traces show sanitized allowlisted planning diagnostics. Never echo raw provider text, rejected secrets, or arbitrary record keys. Unknown write outcomes advise checking saved state/run history; no automatic replay.

Automated verification covers resumed required steps, optional authentication, validation/error redaction, model failure categories and zero target dispatch for rejected proposals. Rendered review is recorded separately after the final build.
